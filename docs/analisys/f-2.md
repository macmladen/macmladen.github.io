# Five sites, one spine — per-site recommendation

*2026-08-16. Input: q.md, the four prior analyses (f-1, o-1, o-2, s-1, t-1), and the reframed brief: all five sites are needed, each needs a credible landing page with newsletter/member/CRM now, the estate should demonstrate architecting-to-need across a multistack practice (Drupal, WordPress, Next, Astro, BaaS), and collaborators must never be blocked by Mladen's own AI-assisted workflow. WordCamp Belgrade: 18–19 Sep 2026 (verified).*

## 1. Premise and the one tension to design around

The earlier consensus was "one stack, five thin sites." The new brief is different and legitimate: the estate itself is the case study, and the case study is *judgment* — five different needs, each answered with the right-sized tool. That only reads as judgment (not as showing off) if every stack in the estate is justified by a need the site actually has. So the governing rule:

> **No stack appears in the estate without a need that argues for it.** Where a need is weak, say so in the decision record.

The cost of heterogeneity is maintenance for one person. The mitigation is: **heterogeneous stacks, homogeneous spine.** Everything that is not the site's core need — tokens, audience/CRM, forms, analytics, hosting patterns, repo conventions — is shared and identical across all five. Static-first wherever possible (nothing to patch); the two update-treadmill systems (WordPress, Drupal) only where their editorial strength is the need, and Drupal only when a team exists to share it.

Second design principle, from the collaborator constraint: **every site that will ever have a non-Mladen editor gets a browser UI** (WP admin, Drupal admin, Keystatic on git-based sites, an admin route on the app site). The AI-assisted git workflow is Mladen's accelerator, not a dependency anyone else inherits.

Third: the "case study" is written, not implied. Each site gets a `/colophon` (how this is built, why) linking to a public decision record on macmladen.com — "why this stack here, and what would make me change it." That page *is* the demonstrator of thinking; it costs an hour per site.

## 3. Per site

### 3.1 macmladen.com — the person (hub)

**Position.** Trust anchor and hub. Everything else borrows credibility from here until it earns its own. Inbound: WordCamp badge-scan, LinkedIn, talks, search. Outbound: contracting leads → Blue Fish; workshops → Koder; listeners → Razgovori. Owns the only blog and the speaker kit.

**Stack: Astro + MDX (git), React islands, Cloudflare Pages.**
Need: single author, content-heavy, must be instantly fast and SEO-clean, English, RSS, occasional rich interactivity (animated hero, a "40 years in tech" timeline, embedded talk decks). Astro answers that exactly: zero JS by default, content collections with typed frontmatter, islands (React + Motion/GSAP) only where interaction lives, view transitions, Pagefind search, OG images via Satori. Editing UI: not needed now; Keystatic drops in later if phone/browser editing is wanted. What would change it: nothing short of a second editor with daily cadence.
Demonstrator: static-first with app-like polish; AI-assisted publishing from notes to PR.

**Menu.** Home · About · Work · Speaking · Writing · Contact — header CTA: *Work with me*. (A `/now` page linked from About; CV at `/cv` with print stylesheet + PDF.)

**Content.**
- Home: who/what-now/proof/CTA in the 8-second test; "meet me at WordCamp Belgrade" block until 19 Sep; latest talk, latest post, network strip.
- About: the edited 40-year story (TI-57 → typography → Mac → web → Drupal → AI tooling) — personality kept, dated details cut; `/now`.
- Work: 3 short write-ups (role, problem, decisions, outcome), including community organizing as delivery (Drupal Camp NS, DaFED, meetup).
- Speaking: topics; talks with event/year/slides/video; the WordCamp session page (abstract, resources, slides, later recording — QR on first/last slide); speaker kit (50/100-word bios, headshots, links). reveal.js decks served under `/talks/<slug>/slides`.
- Writing: the blog. First post: the rebuild itself. Then the decision records (§1) as posts. One post a month keeps it alive.
- Contact: form → Worker → CRM (`brand:macmladen`), interest checkboxes for the other brands, email.
- Colophon.

### 3.2 bluefish.rs — the practice (commercial vehicle)

**Position.** Legal entity, mail domain, invoicing umbrella (Koder workshops invoice through it until Koder justifies its own structure). Where organisations and partner agencies come to buy delivery. Inherits the portfolio from macmladen; hosts `lab.bluefish.rs` for demos (decoupled Drupal demo, realtime experiments) so demonstrators have a home that isn't a live brand.

**Stack: WordPress, custom block theme built from the shared tokens (`theme.json` generated), managed hosting.**
Need: this site's *audience buys WordPress* — regional agency volume is WP, and the WordCamp crowd will look. A fast, page-builder-free block theme with FSE, block bindings for case-study fields, the Interactivity API for the few dynamic bits, minimal plugins (SEO, forms → the shared Worker, Polylang only when EN arrives) demonstrates "WordPress done properly" to the exact market Blue Fish sells to — and gives the mature editor to whoever joins the practice. Weakest link on pure content need (it's five pages), and the decision record should say so: the need is market signal + editorial maturity, and headless WP + Next is the escalation path if a client portal ever appears. Alternative if you'd rather not run WP at all: Next + Payload/Sanity — taste call, but you lose the market-signal argument.
Demonstrator: modern WP for the market that buys WP; tokens → `theme.json`; the site your WordCamp bio links to.

**Menu (SR).** Početna · Usluge · Radovi · Kako radimo · O nama · Kontakt — header CTA: *Razgovarajmo o projektu*.

**Content.**
- Home: "senior-led practice, senior solutions without the agency overhead"; three or four offers; three selected works; the working model in one paragraph; contact.
- Usluge: platform strategy & technical discovery · Drupal & decoupled delivery · WordPress done properly · modernization/rescue/performance · embedded senior development · AI-tooling adoption for teams. Outcomes, not technology walls.
- Radovi: 3 case studies (context, role, constraints, decisions, outcome; anonymised if needed). Community-organising stories count.
- Kako radimo: transparent model — "Blue Fish is an independent practice led by Mladen Đurić, working with trusted specialists when a project needs a broader team." No fake "we".
- O nama: Mladen + network; one honest line of lore ("on Apple platforms since the iPod era"), the price list gone.
- Kontakt: inquiry form → Worker → CRM deal pipeline (`brand:bluefish`, `type:lead`); legal/imprint only with legally correct entity data.
- Lab index; colophon.

### 3.3 koder.rs — education (the member surface)

**Position.** Productises expertise into workshops and courses; the site where "member" means something (accounts, enrollments, materials). Audience arrives from Razgovori listeners, meetups, WordCamp; workshops later attach to the conference as side-events. Its list segment is Koder's real asset.

**Stack: Next.js (App Router) + Supabase (auth, Postgres/RLS, storage), Tailwind, MDX for lesson content, Vercel; Convex for live workshop tools if/when built; Expo app reuses the same backend and types.**
Need: this is the app-shaped site — registration, enrollment, payment, member area with materials/recordings/progress, live session tools (polls, Q&A), certificates. That is exactly what a content-site framework is wrong for and what Next + BaaS is right for. Admin: Supabase Studio + a small `/admin` route so a co-instructor can manage cohorts without touching git. What would change it: nothing — this is the site where the stack *is* the need.
Demonstrator: auth/RLS, server actions, realtime, payments via merchant-of-record, RN app sharing the backend.

**Menu (SR).** Početna · Radionice · Resursi · O Koderu · Prijava — header CTA: *Prijavi se na radionicu*. (Kursevi and Zajednica appear only when they exist; community is a Discord/Telegram link before it's a feature.)

**Content.**
- v1 (landing): promise — "praktične radionice za developere i timove — učiš gradeći nešto stvarno"; the flagship workshop (lean: AI-assisted development with CLI tools; alternates from existing material: DDEV workflows, Drupal + Next) with outline and "register interest"; instructor evidence; company-training inquiry; subscribe (`brand:koder`).
- v2 (after first dated workshop): workshop pages with dates, registration + payment, member area (materials, recordings, progress), resources library (canonical teaching content), testimonials from the first cohort, live tools.
- Colophon.

### 3.4 razgovori.rs — media (distribution engine)

**Position.** The engine that feeds everything: each episode markets Mladen, Koder, Blue Fish, and — most importantly — builds the conference's audience a year early. Also the relationship machine: "come on the podcast" is the highest-leverage outreach for a restarting practice. Its guest list is a network directory. Its subscriber segment is the conference's future list.

**Stack: Astro, content collections for episodes/guests/seasons, persistent audio player via view transitions (`transition:persist`), Keystatic for co-host/producer editing, podcast host for audio + distribution, feed URL owned on the domain, Cloudflare Pages.**
Need: feed-first media site (RSS with enclosures, chapters, transcripts), fast, Serbian, mostly static, but with one app-like requirement — a player that survives navigation. Astro does that on a static site, which is a better demonstrator than an SPA. Keystatic answers the collaborator constraint (browser UI, writes to git, no database). Transcript pipeline: Whisper → MDX → also feeds articles on macmladen. What would change it: a daily-cadence editorial team → a CMS behind the same content layer.
Demonstrator: static site with app-like continuity; owned feed; AI transcript pipeline.

**Menu (SR).** Početna · Epizode · Gosti · O podkastu · Predloži gosta · Pretplati se — header CTA: *Pretplati se*.

**Content.**
- v1 (landing): editorial thesis — "razgovori s ljudima koji oblikuju digitalni rad u Srbiji i regionu: šta grade, kako rade, šta su naučili" (developers, designers, marketers, organisers, founders — the disciplines that must cooperate rarely meet as equals); host; expected guests/subjects; subscribe (`brand:razgovori`); guest suggestion form (→ CRM as `type:guest-suggestion`); "trailer coming" only when recording is underway.
- v2 (publish at three episodes, not one): episode pages (player, show notes, chapters, transcript, guest, links), guest pages, seasons, platform links, clips; podcast structured data.
- Colophon.

### 3.5 conference — convening (independent, co-owned)

**Position.** The community-capital play for Oct 2027, co-owned with Slobodan; must be visibly independent of Blue Fish and not a personal funnel. Its audience forms on Razgovori and at meetups in 2026–27. Nothing public before governance (ownership, decision rights, finance, founder-withdrawal, commercial/nonprofit) and a date exist. Infrastructure — GitHub org, hosting account, domain — is co-owned from day one so no founder is a single point of failure.

**Stack: Drupal (current major) as editorial/data backend, decoupled to a Next.js frontend (next-drupal, on-demand revalidation), same tokens; ticketing external; live "now on stage" board via Convex or Supabase realtime; Expo schedule app consuming the same JSON:API.**
Need: this is Drupal's honest sweet spot and the only site in the estate that has it — several non-technical editors with roles and workflow (CFP submission → review → acceptance), a relational content model (session, speaker, track, room, timeslot, sponsor tier, organiser), bilingual SR/EN in core, and multiple consumers of the same data (site, app, venue screens). It also gives the stalled Drupal/Next scaffold the home it never had, and it's the one decoupled build in the estate — so the estate shows range (classic-modern WP, static Astro, app Next+BaaS, decoupled Drupal) rather than the same pattern twice. What would change it: a co-organiser team already fluent in another CMS.
Demonstrator: decoupled Drupal with real multi-editor workflow; the "I chose *not* to use Drupal for v1 of my own sites, and here's the threshold at which I did" talk.

**Menu (when public; SR/EN).** Home · Program · Speakers · Sponsors · Venue · Tickets · About — header CTA: *Tickets* (pre-launch: *Register interest*).

**Content.** Pre-public: private working doc + interest capture (`brand:conference`) via Razgovori. Public (2027): thesis; team; CFP; program/schedule; speakers; sponsor prospectus; venue/travel; tickets; code of conduct; news; live board during the event.

## 5. Order of work

**Phase 0 — this week: five credible landing pages from one template.** `apps/landing` in the monorepo renders one page per brand from tokens: one-sentence promise, what's coming, why subscribe, subscribe form (→ Worker → CRM with brand tag), cross-links, contact. Deploy to Cloudflare Pages; point macmladen.com, bluefish.rs, koder.rs, razgovori.rs at it (razgovori's 525 disappears by construction; bluefish MX untouched). Stand up the Worker + CRM + analytics at the same time — the spine exists before any real site does. From this point nothing embarrassing is live and every later step is an upgrade, not a rescue.

**Phase 1 — to ~7 Sep: macmladen.com full (Astro).** Home, About/now, Work (3), Speaking + WordCamp session page + speaker kit, Writing (rebuild post), CV, Contact, colophon. Bottleneck is copy, not code — agents scaffold, you write.

**Phase 2 — to ~14 Sep, if talk prep allows: bluefish.rs (WP block theme).** One excellent page + Usluge + 3 Radovi + Kontakt. If it slips, the Phase 0 landing page holds through WordCamp without harm.

**Phase 3 — 14–17 Sep: freeze.** QA, QR/cards → macmladen.com/speaking, bios everywhere aligned, follow-up email drafted.

**Phase 4 — Oct–Nov: razgovori.rs (Astro).** Record episodes 1–3 with WordCamp contacts while warm; publish at three; transcript pipeline live.

**Phase 5 — Q4 2026: koder.rs (Next + Supabase)** once the first workshop has a date; deliver it to the Razgovori audience; payments decision made first.

**Phase 6 — 2027: conference.** Governance with Slobodan → co-owned org, name, domain (H1) → Drupal + Next build (spring) → public with a date (Apr/May) → Oct 2027.

**Cut order if time runs short:** Blue Fish full site → Work write-ups → everything else waits. **Never cut:** Phase 0, macmladen home copy, speaking page, the subscribe spine.
